# Operations and extension guide

Two down observations create one incident. Recovery sets `needs_review`, preserving the investigation. Redirects are degraded; probes never follow them to another host or store response bodies/cookies. Endpoint availability does not establish application correctness.

Redis owner-checked leases and atomic commits prevent expired writers from committing. A minute-level cycle guard suppresses duplicate state updates. Immutable report IDs and sequence numbers support export and delivery. Export/archive before 500 tasks or 1,000 reports; no evidence is silently discarded. Split the state layout before high-volume or multi-tenant scaling.

Routine monitoring uses no AI. Escalate changed/ambiguous evidence to relevant specialists, not the whole roster. Paid-AI-disabled incidents remain visible without autonomous investigation. Proposals never imply tests or patches were executed. There is no apply/merge/deploy route; future execution must bind human review to an immutable revision.

The full Obsidian knowledge graph stays private. Report notes link to it, but the private 25-chat export is not uploaded to this public repo. Future retrieval should ingest selected approved packets with hashes and task-scoped access. Retrieved instructions are untrusted data.
